## 二、公式与边界实现说明

C4 的核心公式为：`最终积分 = 衰减后人气值 × coefficient / 100`。其中，衰减阈值为 `上一轮个人人气值 × DECAY_THRESHOLD_RATIO / 100`。只有当上一轮人气值大于 0 且本轮人气值严格大于阈值时，才触发衰减；超出阈值的部分按 `DECAY_RATE / 100` 折算。若无上一轮记录或上一轮为 0，则不衰减。若最终积分小于 0，则返回 0。

| 场景 | 输入 | 预期 | 实现结果 |
|---|---|---|---|
| 超阈值衰减 | 上轮 100,000，本轮 200,000，系数 100 | 衰减后 155,000，最终 155,000 | 通过 |
| 上轮为 0 或首轮 | 无上一轮 / 上轮 0 | 不衰减 | 通过 |
| 恰好等于阈值 | 上轮 100,000，本轮 150,000 | 不衰减，仅 `>` 触发 | 通过 |
| 系数生效 | 上轮 100,000，本轮 200,000，系数 110 | 155,000 × 110 / 100 = 170,500 | 通过 |
| 负分归零 | 本轮 -5,000 | 最终积分返回 0 | 通过 |

## 五、蓝军说明与待审查点

第一，`scoreBeforeDecay` 当前表示“衰减后、乘系数前的人气值”。Claude 开卡描述中要求返回 `score_before_decay / score_final / decay_applied`，同时公式表述为“积分 = 衰减后人气值 × coefficient / 100”。因此我将该字段定义为乘系数前的基准分值，也就是衰减处理后的值。若 Claude 希望字段名语义严格表示“衰减前原始值”，建议在 C4 审查中明确，我会按其命名要求修正。

第二，“上一轮”的取法采用 `round_id < 当前 round_id ORDER BY round_id DESC LIMIT 1`，即从 `player_round_stats` 中取当前轮之前最近一轮记录。若查不到则按 0 处理，不触发衰减。这与 Claude 开卡中“查不到视为 0”的要求一致。

第三，负分归零只影响 `scoreFinal`，不修改 `popularity` 与 `scoreBeforeDecay`，以保留审计可见性。也就是说，若本轮个人人气为 `-5000`，返回结构中 `popularity=-5000`、`scoreBeforeDecay=-5000`、`scoreFinal=0`。
