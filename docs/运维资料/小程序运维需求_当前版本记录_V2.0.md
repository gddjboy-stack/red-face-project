## 版本定位

本版本为《红颜局中局》抖音小程序运维需求的当前报价版。相较此前 V1.0，本版将计费方式调整为“**基础服务 + 按需值守 + 按次响应 + 小迭代开发 + 企业主体迁移一次性报价**”的组合模式，并明确收窄投票日值守范围，以便按实际用量评估成本。

## 关键变化记录

| 维度 | 当前 V2.0 口径 |
| --- | --- |
| 运维定位 | 面向外部技术服务商报价，强调日常维护强度较低、投票日关键时段稳定性要求高。 |
| 基础技术保障 | 按季度基础服务费报价，不含全天候值守。 |
| 投票日值守 | 仅每周日、周一投票日两个关键时段值守：开启后 30 分钟、结束前 30 分钟。 |
| 紧急响应 | 投票日值守时段内紧急情况按次计费，要求 1 小时内响应并着手处理。 |
| 小迭代开发 | 按人天计费，预计每周期 2—5 个小迭代，单个多为 1—3 人天。 |
| 企业主体迁移 | 新增一次性独立报价项，涉及抖音企业号、抖店、抖音开放平台 API 主体凭证切换。 |
| 交接窗口 | 2026 年 6 月 14 日至 6 月 20 日。 |
| 特别风险 | 2026 年 6 月 21 日后 John 不在岗，企业主体迁移需服务商依据交接文档独立完成，甲方仅能有限远程配合。 |

## 后续引用原则

后续讨论小程序运维报价、外部服务商比选、交接安排、企业主体迁移和投票日值守方案时，应优先引用本 V2.0 版本，除非 John 明确提供更新版本。
