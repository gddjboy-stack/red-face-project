# 第〇部分:Manus 必读的工作纪律

## 0.1 五条铁律(违反任何一条 = 该次提交直接退回)

1. **所有人气值变更只能通过 `PopularityService.applyChange()` 这一个方法。** 任何其他类直接写 popularity_ledger 或 stats 表 = 退回。
2. **人气值用 `long`,系数用 `int`(×100),全项目禁止 `double`/`float` 参与人气值计算。**
3. **本手册给出的代码骨架,照抄结构,只填空,不改架构。** 觉得骨架有问题 → 先问 Claude,不准自己改。
4. **每次提交必须附"验证物"**:单元测试的实际运行输出(不是"我测过了"四个字)。没有验证物 = 没做。
5. **一次只做一个任务卡(见第六部分),做完验证完再领下一张。** 不准并行,不准跳序。

## 0.2 当你不确定的时候

遇到以下任何情况,**停下来,把问题写进提交说明里问 Claude,不要自己猜**:
- 手册没覆盖的场景
