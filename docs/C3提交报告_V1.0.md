## 四、蓝军说明与待审查点

第一，C3 中 `targetType` 为空时只允许 `like/comment` 走场控状态自动归属，其他 source 若未显式指定目标会抛出异常。这是为了避免 `gift/token/manual/refund/team_distribution` 被误归属到当前场控目标，符合“显式付费/人工/卡密行为必须有明确目标”的安全原则。

第二，`pool` 模式下 `target_id` 保持为 `NULL`，与 Schema 注释“pool 时可空”一致。测试中针对 pool 流水使用 `target_id IS NULL` 校验，以避免将 `NULL` 错误等同于 `0`。

第三，C3 同步实现了 `spy` 统计累加能力：当场控模式或显式目标为 `spy` 时，会累加 `player_round_stats.spy_popularity`。虽然本卡验证物未强制要求 spy 测试，但开卡范围写明归属可为 `player/team/spy/pool`，因此我将 spy 的统计更新一并补齐，避免 C3 逻辑存在未支持分支。

第四，P0 修复中 `manual/refund` 允许负值，但 `rawValue=0` 对所有 source 一律拒绝。请 Claude 重点审查这一校验是否与后续 C14 退款逻辑预期一致。
