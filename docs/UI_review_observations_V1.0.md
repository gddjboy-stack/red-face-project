在当前墨刀 DOM 文本中未检索到“打榜”。已观察到的潜在敏感或需控范围词包括“送礼”“购买选手周边”“进入直播间（打赏榜单）”“看广告”“提现”“金币”“积分”。其中部分位于“备用素材（本次不需要）”或墨刀模板页，不一定进入正式小程序；但建议彬少在交付给开发的正式页面集中移除或明确标记为非上线素材，防止误实现。

## 后端能力对照初步结论

当前后端代码已经实现并测试通过的核心能力包括：人气值变更引擎、个人/团队/卧底/总池统计表的累加写入、当前场控集赞目标维护、卡密核销原子抢占、防爆破锁定、核销成功后写真自动收藏，以及 C6 的卡密批量生成和批次导出。`RedeemResult` 当前返回 `success`、`code`、`message`、`tokenId`、`playerId`、`points`、`photoAssetId`、`remainingSeconds`，足以支撑核销成功页的基本字段，但不包含选手姓名、团队名、会员有效期或写真预览 URL。`StatsMapper` 有单个选手/团队/池子的数值查询能力，但缺少面向 UI 的“选手列表 + 组别 + 按序号排序 + 多人统计值”的聚合查询。

关键缺口是：后端目前未发现 `@RestController`、`@RequestMapping`、`@GetMapping` 或 `@PostMapping` 等 API 层注解，说明业务服务虽然存在，但尚未形成小程序可直接调用的 REST 接口。项目自检清单中明确列出 `on_live_metric_delta`、`distribute_team_popularity`、`submit_suspicion` 和阿奇索 H5 参数契约仍属于需要核对的接口契约。数据库虽然已有 `suspicion_votes` 表，但当前代码未发现对应 Mapper/Service/Controller，因此“真相识破”页面仍不能视为已可交付能力。

## 蓝军审查维度补充

在用户提出的四个维度之外，本次建议新增五个审查维度。第一是“上线范围控制”，即区分 P0 彩排必需页面与备用素材，防止墨刀左侧模板页面被开发误读为全部要实现。第二是“平台能力与跳转边界”，尤其是直播间跳转、小黄车、会员群、订单查询、剪贴板读取、用户身份识别等必须逐项确认平台 API 与审核要求。第三是“数据刷新与降级策略”，首页和人气页声称实时更新，但后端目前只有服务层与 Mapper，尚无可调用 API、WebSocket 或轮询契约。第四是“个人信息与肖像/写真授权”，选手头像、写真、昵称、动态和用户收藏都涉及授权、隐私与内容安全边界。第五是“运营话术一致性”，小程序应从“投票/打榜/应援”语境转为“剧情互动/节目进度/数字权益核销/直播伴随工具”语境，尽量避免诱导性和排名化措辞。
