## 二、8/7 卖货方案：不依赖核销的"一人一链接"模式（推荐）

### 核心思路
**每位选手开一个独立商品链接**。谁买了谁的，订单里天然就有，无需卡密、无需核销、无需小程序。

### 流程
1. 抖店为每位选手创建独立商品（实体明信片，标题含选手编号/姓名）
2. 顾客下单 → 阿奇索/客服在会话内发送该选手的数字写真（作为随单赠品）
3. 运营从抖店后台导出订单表 → 按商品统计销量 → 在场控后台批量录入人气
4. 顾客退货 → 运营在抖店看到 → 用后台现有退款功能扣回人气

### 为什么这是好方案
- **8/7 即可用，零审核风险**
- **与自动化路线同源**：现在人工导表，将来接订单接口自动拉，业务逻辑一致，不会白做
- 规避了"卖虚拟商品"问题：卖的是实体明信片，写真是赠品

### 三条必须同步落实的运营配置（今天就能做，不需开发）
1. **抖店商品退货规则**：选配带条件的规则（如"激活/使用后不支持"）
2. **商品详情页显著位置写明**：本商品含数字写真赠品，赠品发出即视为交付；退货需按标价补偿赠品价款
3. **定价与呈现以实体明信片为主体**，写真为附赠权益——避免被认定为变相销售虚拟商品

## 四、抖店订单自动化调研结果（Claude 负责）

### 结论
路线可行，但**卡在资质，不卡在开发**。

### 接入模式
应采用**商家自研（自用型）应用**：有技术能力的商家可创建自用型应用，通过 API 与自有系统对接，实现订单/商品/库存管理。

### 需要的能力
- 订单列表 / 订单详情接口（可获取买了哪个商品 → 对应哪位选手）
- OAuth 2.0 授权 + access_token 定时刷新
- Webhook 推送（2025 年后新特性，可接近实时）
- 售后/退款事件（**需重点确认是否可订阅**，关系到退货自动扣人气）

### ⚠️ 关键长杆：软件著作权证书
申请自研应用需提交**系统功能说明书 + 国家软件著作权证书 + 自研源代码片段**，且**著作权人须与开发者账号认证主体一致**；平台资质审核 1~3 个工作日。

**软著本身**：常规办理约 30+ 个工作日，加急（付费）约 3~10 个工作日。**这与开发速度无关，Manus 再快也压缩不了。**

### 时间估算
| 环节 | 周期 | 备注 |
|---|---|---|
| 软著申请（加急） | 1~2 周 | **长杆，建议今天启动** |
| 创建自研应用 + 资质审核 | 1~3 工作日 | 需软著先到手 |
| 接口权限申请 | 数天 | |
| 开发与联调 | Manus 速度，短 | 业务逻辑已在方案二中跑通 |
| **合计** | **约 3~6 周** | 与 Vincent 预估的 1~2 个月吻合 |

### 建议
1. **今天启动软著加急申请**（主体须与抖店/开放平台认证主体一致，即灵汐互娱）——这是唯一压缩不了的环节，越早越好
2. 软著在办期间，方案二（人工导表）照常运行，业务不中断
3. 软著到手后再创建应用、申请权限、开发，届时可无缝替换人工环节
4. 需确认一项：**退款/售后事件能否订阅**。若不能，退货仍需人工处理，自动化收益打折——请在申请权限时一并确认
