# SELF_CHECKLIST.md

## Manus AI 自检清单 (Java 后端)

### 1. 代码规范与质量
*   [ ] **命名规范**：变量、函数、类名是否清晰、语义化，遵循 Java 命名约定。
*   [ ] **注释规范**：文件头、函数/方法、复杂逻辑是否包含清晰注释。
*   [ ] **魔法数字**：所有常量是否已定义为命名常量。
*   [ ] **依赖注入**：是否采用构造器注入，避免字段注入。
*   [ ] **参数封装**：多参数方法是否封装为 DTO。

### 2. 业务逻辑与防错
*   [ ] **人气值数值类型**：人气值是否使用 `long`，系数是否使用 `int` (×100 存储)，避免 `double`/`float`。
*   [ ] **卡密核销原子性**：是否使用 `@Transactional` + 条件 `UPDATE`，并检查影响行数。
*   [ ] **幂等性**：是否通过数据库唯一约束 + 捕获 `DuplicateKeyException` 确保幂等。
*   [ ] **人气值边界**：积分最低是否为 0，负值只记录在流水和审计中。
*   [ ] **衰减算法**：是否遵循 V2.5 文档中的衰减边界规则。
*   [ ] **目标对象中心**：`apply_popularity_change` 接口是否支持 `target_type` 和 `target_id`。
*   [ ] **只增不改流水账**：所有人气值变动是否记录在 `popularity_ledger` 中。

### 3. 接口契约与数据对齐
*   [ ] **阿奇索变量**：H5 传参是否严格遵循 `t={$卡券信息}&oid={$订单号}` 格式。
*   [ ] **直播免费互动**：`on_live_metric_delta` 接口是否遵循 V2.5 定义。
*   [ ] **团队人气平分**：`distribute_team_popularity` 接口是否遵循 V2.5 定义。
*   [ ] **观众投票卧底**：`submit_suspicion` 接口是否遵循 V2.5 定义。

### 4. 测试与部署
*   [ ] **单元测试**：核心业务逻辑是否覆盖单元测试。
*   [ ] **集成测试**：关键链路是否进行集成测试。
*   [ ] **文档更新**：模块 README、API 契约文档、数据库字典是否同步更新。

### 5. GitHub 同步
*   [ ] **代码提交**：代码是否按模块提交，提交信息清晰。
*   [ ] **自检报告**：是否随代码提交自检报告。
*   [ ] **开发日志**：`DEVELOPMENT_LOG.md` 是否同步更新。
